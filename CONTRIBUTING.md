# Contributing to Tulpar

The full contribution guide is in [docs/CONTRIBUTING.md](docs/CONTRIBUTING.md).

Quick rules:

1. Read the architecture and the relevant contract document before changing code.
2. Never commit secrets, credentials, private keys, or production data.
3. Every database change requires a migration.
4. Every feature requires tests and documentation updates.
5. Authorization decisions belong on the backend.
6. Do not claim a feature works without executing it.
7. Keep changes small, reviewable, and consistent with the existing design.
